# 차근차근 — 구조 설명 (발표 기술 질의응답용)

개발을 깊이 몰라도 발표에서 설명할 수 있게 쉬운 말로 정리했습니다.
한 줄 요약: **차 데이터를 읽어 "점검 엔진"이 판단하고, 결과를 음성과 큰 카드로 알려 준 뒤, 필요하면 내비·열선 같은 실행까지 연결하는 앱**입니다.

---

## 1. 한 장 구조도

```
 ┌────────────────────────────────────────────────────────────────────┐
 │  화면 (Compose)   홈(출발 브리핑·하차 점검) · 점검표 · 등화 점검 · 이력   │
 └───────────────▲────────────────────────────────────────────────────┘
                 │ 화면 상태(UiState)
 ┌───────────────┴────────────────────────────────────────────────────┐
 │  MainViewModel   시동 켜기/끄기 흐름 진행, 버튼·음성 응답 처리, 실행 연결    │
 └───────────────▲────────────────────────────────────────────────────┘
                 │ 차 상태 묶음(VehicleSnapshot) 넣고 → 점검 결과(Finding) 받기
 ┌───────────────┴────────────────────────────────────────────────────┐

 └───────────────▲────────────────────────────────────────────────────┘
                 │ 인터페이스만 본다 (차종·환경이 바뀌어도 엔진은 그대로)
 ┌───────────────┴────────────────────────────────────────────────────┐
 │  데이터 계층                                                          │
 │  VehicleDataSource │ ScheduleSource │ NavigationSource │ WeatherSource │
 │  Voice / VoiceInput │ DrivingStateSource │ HistoryStore(차 안 파일)     │
 └───────────────▲────────────────────────────────────────────────────┘

 │  Pleos SDK: Vehicle 2.3.2 · NaviHelper 3.0.5 · TextToSpeech/SpeechToText 3.3.1 │
 │  AAOS 표준 Car API: 시동·주차 브레이크·기어·주행 중 화면 제한               │
```

앱은 두 가지로 빌드됩니다.

| 빌드 | 앱 이름 | 데이터 | 용도 |
|---|---|---|---|
| `pleos` | 차근차근 | Pleos SDK·AAOS·캘린더·날씨 실제 값 | 실차·Pleos 에뮬레이터 |
| `mock` | 차근차근 데모 | 데모 시나리오 6종(겨울 아침, 경고등 등) | 시연 영상, 어떤 에뮬레이터에서도 실행 |

두 빌드는 **점검 엔진·화면 코드가 완전히 같고**, 데이터 계층만 바뀝니다.

## 2. 데이터 흐름

### 시동을 켤 때 (출발 브리핑)
1. 시동 켜짐을 받는다 (AAOS `IGNITION_STATE`, 받을 수 없는 환경이면 앱을 연 순간 / 데모는 "시동 켜기" 버튼)
2. 차 상태를 한 번에 읽는다: 주행거리, 주행가능거리, 경고(엔진오일·브레이크액·변속기 오일·워셔액), 문·창문·등, 주차 브레이크·기어
3. 차에 바깥 기온 값이 없으면 날씨 예보(Open-Meteo)의 현재 기온을 넣는다
4. 목적지를 정한다: ① 내장 내비가 길안내 중이면 그 목적지와 남은 거리(NaviHelper `getRouteStateInfo`·`getDestinationInfo`) ② 캘린더에서 4시간 안 다음 일정 — 장소 좌표(일정 설명의 `geo:` → 없으면 지오코딩) → NaviHelper `requestTrip` 으로 거리·시간 ③ 둘 다 없으면 출발 항목 없이 차 상태만 점검
   - 시동 후 운전자가 내비에서 목적지를 정해 길안내가 시작되면(`onRouteStarted`) 남은 거리와 주행가능거리를 다시 비교해, 부족할 때만 음성으로 알린다
   - 앱이 화면에 다시 올 때마다(`onStart`) 길안내 중인 목적지를 한 번 더 조회한다(앱이 떠 있는 동안 시작한 안내는 `onRouteStarted`가 안 올 수 있어서). 같은 목적지·같은 결과면 한 번만 말한다
5. 점검 엔진이 판단: 출발 여유, 주행가능거리 부족, 경고 풀이, 정비 시기, 계절 점검, 공기압 추세, 반복 경고
6. 음성 브리핑 조합: **일정 먼저, 그다음 심각한 순서로 최대 3건**만 말한다. 나머지는 카드로
7. "겨울 출발 준비 켤까요?"를 물었다면 말이 끝난 뒤 6초 동안 "응/아니"를 듣는다 → "응"이면 열선·공조 실행

### 시동을 끌 때 (하차 점검)
1. 시동 꺼짐(ON→OFF)을 받는다 (데모는 "시동 끄기" 버튼)
2. 실내등·전조등·문·창문·주차 브레이크·기어를 읽고, 오늘 밤 최저기온 예보를 가져온다(4초 넘으면 생략)
3. 하차 점검: 켜진 등, 덜 닫힌 문, 열린 창문, 영하 10도 이하 예보면 블랙박스 주차 녹화 끄기 권유. 기어가 P인데 주차 브레이크만 풀려 있으면 "경사로라면 채워 주세요" 참고 카드(음성 제외), 기어가 P가 아니거나 모르면 주의 + 음성
4. 음성으로 "내리기 전에 확인해 주세요. …" + 카드
5. 화면이 열려 있는 동안 문·창문·등 상태가 바뀌면(리스너) 카드가 바로 다시 계산된다 — 문을 닫으면 "문 덜 닫힘" 카드가 사라짐

### 주행 기록 (시동 신호가 없어도)
- 주행 중 화면 제한(CarUxRestrictions)이 켜졌다 꺼지는 시점을 "마지막 운행"으로 저장 → 오래 안 탄 차의 첫 운행 안내가 실차에서도 동작

### 장소 검색이 실패하면
- 주유소·정비소 경유는 공개 지도 서버(Overpass)로 찾는다. 서버가 응답하지 않으면 "내비게이션에서 '주유소'를 검색해 주세요" 안내와 **다시 찾기** 버튼(1분에 3번까지)

### 화면 구성 (홈)
- 위: 요약 줄 — 조치 필요 건수(위험·주의), 시동 상태, 다음 일정, 누적 주행거리, 바깥 기온
- 왼쪽 "지금 조치할 것": 위험·주의 전부 + 지금 실행할 동작이 있는 카드(길안내, 경유지, 겨울 출발 준비, 등화 점검). 아래에 "확인한 항목 이상 없음 (N개)"
- 오른쪽 "음성 브리핑 · 안내 · 다가오는 점검": 방금 말한 내용, 계절 안내, 다음 정기점검
- 카드를 실제로 재서 **스크롤 없이 들어가는 만큼** 보여 주고, 넘칠 때만 "N건 더 보기"
- 주행 중: 음성 브리핑 문장(40sp)과 큰 버튼(최대 3개)만, 아래 탭은 잠금
- 시동 꺼짐(점검 전): 가운데 안내 문장 + 큰 "시동 켜기"(데모만)

## 5. 점검 엔진 판정 규칙 요약

| 규칙 | 기준 | 코드 위치 |
|---|---|---|
| 공기압 조금 낮음 | 권장값의 90% 미만 → 권장 | `DailyCheck.LOW_RATIO` |
| 공기압 매우 낮음 | 권장값의 80% 미만 → 긴급 | `DailyCheck.VERY_LOW_RATIO` |
| 출발 여유 | 일정 시각 − (지금 + 이동 시간 + 도착 후 10분) | `DepartureBriefing.BUFFER_MIN` |
| 주행가능거리 부족 | 주행가능거리 < 경로 거리 × 1.3 → 주유소·충전소 경유 제안 | `DepartureBriefing.RANGE_MARGIN` |
| 정비 임박 | 남은 거리 500km 이하 또는 남은 날 30일 이하 | `PeriodicCheck.SOON_KM`, `SOON_DAYS` |
| 가혹 조건 | 최근 10회 이상 운행 중 8km 미만 짧은 운행이 절반 이상, 또는 급제동 100km당 10회 이상 → 짧은 주기 적용 | `DrivingPattern` |
| 겨울 출발 준비 | 바깥 기온 3도 이하 → 열선·공조 제안 | `SeasonalCheck.COLD_PRESET_C` |
| 장기 미운행 | 14일 이상 → 공기압·배터리 확인 안내 | `SeasonalCheck.LONG_IDLE_DAYS` |
| 계절 구분 | 11월 동절기 전, 12~2월 동절기, 6월 하절기 전, 7~8월 하절기 | `SeasonalCheck.phase` |
| 한 바퀴 누설 | 21일 동안 3번 이상 기록, 한 바퀴만 주당 7kPa 이상 하락(다른 바퀴는 3kPa 이하) | `FocusWatch` |
| 반복 경고 | 30일 안 같은 경고 3번 이상 → 정비소 점검 권유 | `FocusWatch.REPEAT_*` |
| 한파 블랙박스 | 오늘 밤 최저 영하 10도 이하 | `ExitCheck.DASHCAM_COLD_C` |
| 경고 심각도 | 엔진오일 압력·냉각수 온도·브레이크 계통 = 긴급, 충전·엔진 점검 = 주의, 오일·브레이크액 "매우 부족" = 긴급, "부족" = 주의, 워셔액 = 참고 | `WarningTranslator` |
| 음성 개수 | 일정 먼저 + 심각한 순 최대 3건 | `BriefingComposer.MAX_SPOKEN` |

## 6. 안전 설계

- **주행 중에는 음성만**: AAOS 주행 제한 신호가 오면 점검표·등화 점검·이력 탭을 잠그고, 홈에는 음성 안내(40sp) + 큰 버튼(112dp)만 남깁니다.
- **점검표·등화 점검은 주차 상태에서만**: 주차 브레이크가 채워져 있거나 기어가 P일 때.
- **제어 전 확인**: 열선·공조·등화는 운전자가 버튼을 누르거나 "응"이라고 답한 뒤에만 켭니다. 켤 수 없는 차면 "직접 켜 주세요"로 안내합니다.
- **글씨·버튼 크기**: 실제 차 화면은 밀도가 낮아 글씨가 작게 보여서, 홈·모든 탭을 본문 24sp·제목 30sp·버튼 56dp 이상으로 키웠습니다(주행 중·등화 점검 답 버튼 112dp).
- **데이터는 차 안에**: 점검·정비 이력은 차 안 앱 저장소 파일에만 저장합니다. 서버로 보내지 않습니다.
  외부로 나가는 것은 날씨·장소 검색용 **좌표 한 점**뿐이고, 개인 식별 정보는 보내지 않습니다.

## 7. 예상 질문 22개와 짧은 답

1. **지원 안 되는 차종은?** — 시작할 때 기능별 지원 여부(capability)를 확인해 되는 것만 씁니다. 값을 못 읽으면 "눈으로 확인"으로 바꿔 안내하므로 앱이 멈추지 않습니다.
2. **공기압 API를 왜 안 썼나?** — 공식 샘플이 `Tire.getTirePressure`를 공개 API에서 뺐습니다. 사무국에 문의 중이고, 엔진은 이미 공기압 추세까지 만들어 두어서 허용되면 한 줄 연결로 켜집니다. 데모 앱에서는 시연합니다.
3. **경고등은?** — 마찬가지로 `Safety.getTelltalesInfo`가 비공개라, 공개된 엔진오일·브레이크액·변속기 오일·워셔액 상태로 경고를 만듭니다.
4. **배터리(차량) 소모는?** — 상시 감시하지 않습니다. 시동 켤 때·끌 때 한 번씩 읽고, 리스너는 화면이 보일 때만 등록합니다.
5. **개인정보는?** — 이력은 차 안에만 저장합니다. 날씨·장소 검색에는 좌표만 보내고 계정·이름은 보내지 않습니다.
6. **오프라인에서는?** — 점검 엔진·음성(ON_DEVICE)·차 데이터는 오프라인에서도 동작합니다. 날씨·주유소 검색만 생략됩니다.
7. **테스트는 어떻게?** — 점검 엔진은 안드로이드와 분리된 순수 코드라 단위 테스트로 검증합니다(엔진 30개 + 홈 화면 배치 규칙 18개). 차 연동은 Pleos 에뮬레이터 + Virtual Console로 문·등·기어를 바꿔 가며 확인했습니다.
8. **시동을 어떻게 아나?** — AAOS 표준 `IGNITION_STATE`를 구독합니다. 에뮬레이터는 이 값을 주지 않아 버튼으로 대신했습니다(실차 동작은 사무국에 확인 중).
9. **운전 중에 화면을 보게 하지 않나?** — 주행 제한 신호에서 화면을 잠그고 음성으로만 안내합니다.
10. **열선을 마음대로 켜지 않나?** — "켤까요?"에 "응" 또는 버튼으로 확인한 뒤에만 켭니다.
11. **음성 인식이 틀리면?** — "응/아니"처럼 짧은 답만 받고, 애매하면 무시합니다. 버튼이 항상 함께 있습니다.
12. **주유소는 어떻게 찾나?** — NaviHelper에 장소 검색이 없어 OpenStreetMap 공개 데이터로 주변 3km(없으면 10km)를 찾고, 목적지 방향을 우선해 NaviHelper 경유지로 넣습니다.
13. **일정은 어디서? 일정이 없으면?** — 목적지는 내장 내비에 설정된 목적지를 먼저 쓰고, 없으면 차의 안드로이드 캘린더 일정을 씁니다. 둘 다 없으면 차 상태 점검만 합니다. 휴대폰 캘린더가 차로 동기화되는지는 사무국에 확인 중입니다.
14. **정비 주기 숫자 근거는?** — 지금은 샘플 값입니다. 차종 정보(CarInfo)로 취급설명서의 정기점검표 값을 고르도록 바꿀 예정입니다.
15. **여러 사람이 타는 차는?** — 시동 때마다 그때 운전하는 사람에게 말하는 방식이라, 누가 타도 같은 안내를 받습니다. 가족 공유는 동의한 경우에만(예정).
16. **왜 하차 점검인가?** — 긴급출동 1위가 배터리 방전이고, 실내등·문·한파 블랙박스가 주요 원인이라 시동 끄는 순간에 잡습니다.
17. **등화 점검은 왜?** — 자동차 검사 불합격 1위가 등화장치입니다. 앱이 등을 하나씩 켜 주고 운전자가 "켜졌어"로 답합니다.
18. **Pleos 외 차에서도?** — 데이터 계층만 바꾸면 됩니다. 점검 엔진은 차 회사와 무관한 순수 코드입니다.
19. **앱이 꺼져 있으면?** — 현재는 앱이 실행 중일 때 동작합니다. 시동 때 자동 실행 허용 범위는 사무국에 확인 중입니다.
20. **데모와 실제의 차이는?** — 화면·엔진은 같고 데이터만 시나리오입니다. 실연동 앱은 같은 화면을 실제 SDK 값으로 채웁니다.
21. **디자인은 어떻게?** — 운전석에서 한눈에 읽히게 "지금 할 일"(왼쪽)과 "들은 내용·다가올 일"(오른쪽) 두 칸으로 나눴고, 심각도는 색·아이콘·테두리로 구분합니다. 실제 차 화면(Pleos 에뮬레이터)에서 녹화를 보며 글씨를 1.35배로 키우고, 카드를 스크롤 없이 들어가는 만큼만 보여 주도록 조정했습니다. 주행 중에는 화면 대신 음성과 큰 버튼만 남깁니다.
22. **공개 서버가 장애 나면?** — 날씨·장소 검색만 공개 서버를 씁니다. 날씨가 안 오면 바깥 기온·한파 안내만 빠지고, 장소 검색이 실패하면 "내비게이션에서 검색해 주세요" 안내와 "다시 찾기" 버튼을 보여 줍니다. 점검·음성·차 데이터는 서버 없이 동작합니다. 국내 지도 API는 교체 지점만 만들어 두었습니다.
